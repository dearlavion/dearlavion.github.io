Your SSD is actually a **128 GB** drive, which Linux shows as 119.2 GiB. All of it is accounted for, and **14.75 GiB is sitting unused** that you can give to your VMs.

### The disk, piece by piece

```
sda  119.2G  ← whole SSD (128 GB marketed = 119.2 GiB)
├─ sda1   1M    BIOS boot partition (tiny, needed for booting)
├─ sda2   1G    EFI partition (/boot/efi, bootloader files)
└─ sda3  118.2G LVM "physical volume", everything else lives in here
```

### Inside `sda3`: the `pve` volume group (118.24 GiB)

|Volume|Size|What it is|
|---|---|---|
|`pve-root`|39.56 GiB|Proxmox OS → your **`local`** storage|
|`pve-swap`|8.00 GiB|Swap for the host|
|`pve-data` (`_tdata`)|53.93 GiB|Thin pool data → your **`local-lvm`**|
|`pve-data_tmeta`|1 GiB|Thin pool metadata (tracks which blocks each VM disk uses)|
|`lvol0_pmspare` (hidden)|1 GiB|Spare copy of that metadata for repairs. It doesn’t show in `lvs`, but it takes up space.|
|**VFree**|**14.75 GiB**|**Not assigned to anything**|
|**Total**|**118.24 GiB** ✅||

`pve-data` appears twice in `lsblk` only because it’s built from the data part and the metadata part together. It’s one 53.93 GiB pool, not two.

`Data% 0.00` on `data` confirms the pool is empty, as expected.

### Why 14.75 GiB is unused

The installer keeps about 1/8 of the disk free for LVM snapshots of the host volumes. Proxmox doesn’t need it for VMs on LVM-thin, so in a homelab it’s safe to use.

### Recommended: give it to `local-lvm`

bash

```bash
lvextend -l +100%FREE pve/data
lvs pve/data
pvesm status
```

`local-lvm` grows from about **54 → 68.7 GiB**. This is safe to run now, with no reboot and no data loss.

**Optional:** shrink swap from 8 to 4 GiB to gain another 4 GiB. With 16 GB of RAM and fixed VM memory, 4 GiB of swap is plenty. Run this **before** the `lvextend` above, so the freed space goes to the pool too:

bash

```bash
swapoff -a
lvreduce -L 4G pve/swap -y
mkswap /dev/pve/swap
swapon -a
```

Used 14.75 free space then reduced swap memory from 8 to 4 GB
