#### Host swap behavior

```bash
echo 'vm.swappiness=10' > /etc/sysctl.d/99-swappiness.conf
```

- `vm.swappiness`: a kernel setting from 0 to 100 that controls how eagerly Linux moves memory to swap. The default of 60 is fairly eager. 10 means “only when RAM is nearly full”, which is better on a VM host.
- `echo '...' > file`: writes that line into a new file.
- `/etc/sysctl.d/`: a folder of kernel settings applied at every boot. The `99-` prefix makes it load last, so it wins over other settings.

```bash
sysctl --system | grep swappiness
```

- `sysctl --system`: loads every file in `/etc/sysctl.d/` **now**, without a reboot.
- `| grep swappiness`: shows only the lines containing “swappiness”, to confirm it’s set to 10.


#### SSH key

```bash
ls /root/.ssh/id_ed25519.pub || ssh-keygen -t ed25519 -N "" -f /root/.ssh/id_ed25519
```

- `ls file`: checks whether the key already exists.
- `||`: run the next command **only if** the first one failed, i.e. there’s no key yet.
- `ssh-keygen`: creates an SSH key pair: a private key (stays secret) and a `.pub` public key (gets copied to servers).
    - `-t ed25519`: key type. Modern, short and secure.
    - `-N ""`: empty passphrase, so automation can use it without prompting. Fine for a homelab host.
    - `-f`: where to save the file.

The public key gets injected into every VM in step 4, so the host can SSH in without a password.

### Create the cloud-init snippet (required, don’t skip)

#### Why you need this

Template 9000 is set up to read a small file called **`vendor.yaml`** every time a VM made from it boots. **If the file doesn’t exist, the VM won’t start.** You saw this as:

```
TASK ERROR: volume 'local:snippets/vendor.yaml' does not exist
```

The file’s job is to install the **QEMU guest agent** inside each new VM automatically. The guest agent is a small helper program that lets Proxmox show the VM’s IP, shut it down cleanly, and back it up safely.

#### What to do

Open **pve → Shell** in the Proxmox web UI. Copy the **whole block** below, paste it, and press **Enter**:

bash

```bash
# 3a. Let the 'local' storage hold snippet files
pvesm set local --content iso,images,backup,import,vztmpl,snippets

# 3b. Make the folder for snippets
mkdir -p /var/lib/vz/snippets

# 3c. Write the vendor.yaml file
cat > /var/lib/vz/snippets/vendor.yaml <<'EOF'
#cloud-config
package_update: true
packages:
  - qemu-guest-agent
runcmd:
  - systemctl enable --now qemu-guest-agent
EOF
```

Nothing is printed when it works. That’s normal.

#### Check that it worked

Paste this:

bash

```bash
cat /var/lib/vz/snippets/vendor.yaml
pvesm list local --content snippets
```

✅ You should see the file’s 7 lines, and then:

```
Volid                        Format    Type        Size  VMID
local:snippets/vendor.yaml   snippet   snippets     ...
```

If the second command prints nothing, step 3a didn’t apply. Run the `pvesm set local …` line again.

#### What each part means

|Line|Plain meaning|
|---|---|
|`pvesm set local --content …,snippets`|“The `local` storage may hold snippet files.” Without this, Proxmox won’t look for `vendor.yaml`, even if the file exists.|
|`mkdir -p /var/lib/vz/snippets`|Create the folder where `local` keeps snippets. `-p` means “no error if it already exists”.|
|`cat > /var/lib/vz/snippets/vendor.yaml <<'EOF'`|“Write everything from the next line up to `EOF` into this file.”|
|`EOF` (last line)|End of the file’s contents. It must be alone on its own line.|

What the 7 lines **inside** the file tell the new VM on its first boot:

|Line in the file|Plain meaning|
|---|---|
|`#cloud-config`|“This is a cloud-init settings file.” It must be the first line, exactly like this.|
|`package_update: true`|Run `apt update` first.|
|`packages:` + `- qemu-guest-agent`|Install the guest agent.|
|`runcmd:` + `- systemctl enable --now qemu-guest-agent`|Start the guest agent now, and at every boot.|

#### Why it’s called “vendor”

A new VM gets its first-boot settings from **three places**:

|Place|Filled by|Contains|
|---|---|---|
|**user**|the **Cloud-Init tab** in Proxmox|username, password, SSH keys|
|**network**|the **Cloud-Init tab** in Proxmox|IP, gateway, DNS|
|**vendor**|**this file**|extra steps (install the guest agent)|

Because it uses the **vendor** slot, this file **adds** to what you set in the Cloud-Init tab and **doesn’t replace it**. Your IP and SSH keys still apply.

**You only do this once per Proxmox host.** Every VM cloned from template 9000 (104 now, and 100–103 later) uses the same file.
