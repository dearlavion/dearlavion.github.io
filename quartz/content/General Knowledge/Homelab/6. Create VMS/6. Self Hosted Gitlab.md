# **Phase 2 — Install Docker on the deployment VM**

Even though you're not building images here, Docker is needed to pull and run containers.

### **Step 2.1 — Install Docker Engine**

Run:

```
sudo install -m 0755 -d /etc/apt/keyrings

sudo curl -fsSL \
  https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc

sudo chmod a+r /etc/apt/keyrings/docker.asc
```

Add the Docker repository:

```
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
```

Install Docker:

```
sudo apt update

sudo apt install -y \
  docker-ce \
  docker-ce-cli \
  containerd.io \
  docker-buildx-plugin \
  docker-compose-plugin
```

Start Docker:

```
sudo systemctl enable docker
sudo systemctl start docker
```

Verify:

```
sudo docker version
sudo docker compose version
sudo docker run hello-world
```

### **Step 2.2 — Create a deployment user**

I recommend a dedicated Linux user called `runner`.

```
sudo adduser runner
```

Allow it to execute Docker commands:

```
sudo usermod -aG docker runner
```

**Important security note:** Membership in the Docker group effectively grants root-level control of the VM. Only trusted workflows should run on this runner. Restrict deployment to your private repository and `main` branch.


# **Phase 3 — Configure GitHub Container Registry (GHCR)**

Your GitHub-hosted runner will push images to GHCR. Your Proxmox deployment VM will pull them.

The two machines need different permissions:

|Machine|GHCR permission|
|---|---|
|GitHub-hosted runner|Write packages|
|Proxmox deployment VM|Read packages|

### **Step 3.1 — Configure GitHub Actions permissions**

Go to your GitHub repository:

1. Settings
    
2. Actions
    
3. General
    
4. Workflow permissions
    
5. Allow GitHub Actions to read and write repository contents permissions (where applicable, select read and write permissions).
    

We'll also explicitly declare package permissions in the workflow:

```
permissions:
  contents: read
  packages: write
```

### **Step 3.2 — Create a read-only GHCR token**

For your deployment VM, create a GitHub Personal Access Token (classic).

Go to:

[GitHub Personal Access Tokens](https://github.com/settings/tokens?utm_source=chatgpt.com)

1. Generate new token (classic).
    
2. Give it a name: `proxmox-vm-runner`.
    
3. Select `read:packages`.
    
4. Generate the token.
    
5. Copy it somewhere safe.

```
GIT PAT

proxmox-vm-runner

GITHUB_TOKEN
```

Do not commit this token to your repository.

### **Step 3.3 — Authenticate your deployment VM**

Switch to the runner user:

```
sudo su - runner
```

Login to GHCR:

```
echo "GITHUB_TOKEN" | docker login ghcr.io \
  -u dearlavion \
  --password-stdin
```

Expected:

```
Login Succeeded
```

Docker stores the authentication configuration under the runner user's home directory.

**Note:** If your GHCR packages are private, make sure the token's account has permission to read those packages.

# **Phase 4 — Install your GitHub self-hosted runner**

This is where your Proxmox VM becomes a GitHub Actions runner.

### **Step 4.1 — Open your GitHub repository**

Navigate to:

`Repository → Settings → Actions → Runners`

Click:

New self-hosted runner

Select:

- Operating system: Linux
    
- Architecture: x64 (assuming your VM is x86_64)
    

GitHub will display installation commands specific to your repository and the current runner version.

### 1. Download the Runner

Open your Ubuntu VM terminal.

#### Create a directory

```
mkdir actions-runner && cd actions-runner
```

#### Download the latest runner package

```
curl -o actions-runner-linux-x64-2.338.2.tar.gz -L https://github.com/actions/runner/releases/download/v2.338.2/actions-runner-linux-x64-2.338.2.tar.gz
```

#### Validate the download hash (Optional)

```
echo "baebf204307bac6193480852732f0aba2ae97b6c5597c244f4d5558390147c40  actions-runner-linux-x64-2.338.2.tar.gz" | shasum -a 256 -c
```

Expected output:

```
actions-runner-linux-x64-2.338.2.tar.gz: OK
```

#### Extract the installer

```
tar xzf ./actions-runner-linux-x64-2.338.2.tar.gz
```

---
#### Configure the runner

```
./config.sh --url https://github.com/dearlavion/dearlavion-homelab --token YOUR_RUNNER_TOKEN
```

> [!WARNING]  
> Replace `YOUR_RUNNER_TOKEN` with the temporary registration token generated by GitHub. Do not share or commit this token.

### 4. Use the Self-Hosted Runner in GitHub Actions

In your GitHub Actions workflow file (`.github/workflows/deploy.yml`), configure the job to use your self-hosted runner:

```
name: Deploy to Proxmox  
  
on:  
  push:  
    branches:  
      - dev  
  
jobs:  
  deploy:  
    runs-on: [self-hosted, proxmox-deploy]  
  
    steps:  
      - name: Checkout repository  
        uses: actions/checkout@v4  
  
      - name: Test deployment  
        run: echo "Deploying dev branch to Proxmox!"
```

### **Step 4.5 — Install the runner as a Linux service**

You don't want to manually start your runner every time the VM reboots.

Exit the runner user shell to switch to root user:

```
exit
```

Then:

Check where is the directory of actions-runner/
```
cd /home/runner/actions-runner/

sudo ./svc.sh install runner

sudo ./svc.sh start
```

Check status:

```
sudo ./svc.sh status
```

Expected result:

```
Active: active (running)
```

Go back to GitHub:

`Repository → Settings → Actions → Runners`

You should see:

**vm-runner**

Idle

Your runner is now registered and listening for jobs.
