Templates are useful for easy cloning and avoid manual ISO images re-setup

### Build the template (VM 9000)

bash

```bash
cd /var/lib/vz/template/iso
wget https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
```

- `cd`: change into the folder used for install media.
- `wget`: downloads a file from the internet.
- `noble`: Ubuntu 24.04’s codename. `current` = latest build, `amd64` = 64-bit Intel/AMD.

bash

```bash
qm create 9000 --name ubuntu-2404-tmpl --ostype l26 \
  --cpu host --cores 2 --memory 2048 \
  --net0 virtio,bridge=vmbr0 --scsihw virtio-scsi-single
```

Creates an **empty VM shell** with no disk yet.

- `9000`: the VM ID. A high number keeps templates apart from real VMs.
- `--name`: display name.
- `--ostype l26`: tells Proxmox the guest is Linux 2.6+ (any modern Linux), so it picks suitable defaults.
- `--cpu host`: passes your real CPU model and its features to the VM. Fastest option. The only downside is that live migration needs identical CPUs, which doesn’t matter with one host.
- `--cores 2`, `--memory 2048`: placeholder sizes (2048 MB = 2 GB). Each clone overrides them.
- `--net0 virtio,bridge=vmbr0`: first network card, using the **virtio** driver (paravirtualized, much faster than an emulated card), plugged into the `vmbr0` bridge.
- `--scsihw virtio-scsi-single`: the disk controller type. Fast, and gives each disk its own controller, which allows the `iothread` option for better performance.
- `\`: continues the command on the next line.

bash

```bash
qm set 9000 --scsi0 local-lvm:0,import-from=/var/lib/vz/template/iso/noble-server-cloudimg-amd64.img,discard=on,ssd=1
```

Adds the **main disk**, built from the cloud image.

- `qm set 9000`: changes VM 9000’s settings.
- `--scsi0`: first disk on the SCSI controller.
- `local-lvm:0`: create the disk on `local-lvm`. The `0` means “size taken from the imported image”.
- `import-from=...`: copy the cloud image’s contents into this new disk.
- `discard=on`: when the guest deletes files and runs TRIM, Proxmox releases those blocks back to the **thin pool**. Without it, the pool’s usage only ever goes up.
- `ssd=1`: tells the guest the disk is an SSD, so Ubuntu enables its weekly TRIM job (`fstrim.timer`) and SSD-friendly behavior.

bash

```bash
qm set 9000 --ide2 local-lvm:cloudinit --boot order=scsi0
```

- `--ide2 local-lvm:cloudinit`: adds a small virtual **cloud-init drive**, a few MB. Proxmox writes your settings (user, SSH key, IP) into it, and cloud-init inside the VM reads it at boot. IDE is used because every OS can read it.
- `--boot order=scsi0`: boot from the main disk only.

bash

```bash
qm set 9000 --serial0 socket --vga serial0 --agent enabled=1
```

- `--serial0 socket`: adds a virtual serial port. Ubuntu cloud images send their console output there.
- `--vga serial0`: makes the web UI console use that serial port. Without this, the noVNC console can look blank or frozen.
- `--agent enabled=1`: tells Proxmox to expect the QEMU guest agent (installed by the snippet).

bash

```bash
qm set 9000 --ciuser ubuntu --sshkeys /root/.ssh/id_ed25519.pub --ipconfig0 ip=dhcp
```

Cloud-init settings:

- `--ciuser ubuntu`: the login user to create.
- `--sshkeys`: the public key to put in that user’s `authorized_keys`, so you can SSH in without a password.
- `--ipconfig0 ip=dhcp`: default network setting. Each clone replaces it with a static IP.

bash

```bash
qm set 9000 --cicustom "vendor=local:snippets/vendor.yaml"
```

- `--cicustom`: attaches a custom cloud-init file.
- `vendor=local:snippets/vendor.yaml`: use your snippet as the **vendor data** (the slot explained in step 3).

bash

```bash
qm template 9000
```

Turns VM 9000 into a **read-only template**. It can’t be started anymore, only cloned. Its disk is renamed `base-9000-disk-0`.
