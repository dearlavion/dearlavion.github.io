Test it layer by layer on the server. Each step checks one more piece:

bash

```bash
ping -c 3 192.168.8.1        # 1. Can it reach your router?
ping -c 3 1.1.1.1            # 2. Can it reach the internet (by IP)?
ping -c 3 google.com         # 3. Does DNS work (names → IPs)?
curl -sI https://google.com | head -1   # 4. Do web downloads work?
```

### Reading the results

|Step|✅ Works means|❌ Fails means|Fix|
|---|---|---|---|
|**1. Router**|The server is on your home network|Network config or cable problem|Check `ip -br addr` shows `192.168.8.50`, and check the cable|
|**2. `1.1.1.1`**|**The server has internet**|Wrong gateway|Run `ip route`. It should show `default via 192.168.8.1`.|
|**3. `google.com`**|DNS works|DNS is wrong (likely your issue now)|Set the DNS in `/etc/resolv.conf` to `1.1.1.1` (see my last message)|
|**4. `curl`**|Full internet: downloads, updates and installs work|Usually DNS, or a firewall/proxy|Fix step 3 first|

If Step 3 fails: That’s a DNS problem, as expected. Here’s the fix.
